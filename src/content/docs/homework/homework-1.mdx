The goal of homework 1 is to get us familiar with the LLVM API and writing simple passes. You will implement a few basics passes that use the loop analyses from LLVM.

> For iterating over functions, ignore functions that are declarations (i.e., have no body). You can check this using the `isDeclaration()` method on the `Function` class.

### Submission
Please submit your report on canvas and code (from problem 2 onwards) on gradescope.

**Q1.1:** Try using `-Wno-c++11-narrowing`  in `ALLFLAGS`.

**Report format:**
The statistics to be reported (questions 2, 3.1, 3.2) should be returned as  Result objects. These are printed by the printer passes and autograded. Parts 3.3 and 3.4 should follow the report_format.md format. Part 4 also should use the Result object, but it will not be autograded.

**Question 2.4:** There are three things to calculate: the average number of dominators per basic block over all functions, the function where the block with the max number of dominators is present, and the same for the minimum.

**Iterating over functions:** Make sure you ignore function declarations (check this either with F.isDeclaration() or if F.size() is zero.)


**Q3.1 JSON Printing:** (or any value printing in general)
  Use getNameOrAsOperand() instead of getName() which works even if the value does not have a name (like basic blocks that are serially numbered with the SSA values).

**Q3.3 Reachability:** If Block A reaches Block B, consider all SSA variables defined in A to "reach" B. (With this, either all or none of the definitions in A "reach" B).

> You don't need to resubmit your work if you have already submitted it by checking for the SSA dominance condition instead.

**Q3.2 Cycle Detection:** You can stop at detecting the outermost cycles (the maximal SCC set) and count the number of entries. The benchmarks provided may not have multi-entry cycles, so to test, create some small examples. It will, of course, be graded on hidden inputs.
